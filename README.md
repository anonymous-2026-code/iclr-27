# Anonymous Oracle-TTA

Code for Frozen, Practical and Oracle test-time adaptation in reconstruction-based
time-series anomaly detection. This repository contains implementation,
configuration, data-identification manifests and usage instructions. Datasets,
trained weights, experimental results, figures and audit reports are not bundled.
All analysis commands consume outputs generated by your own runs.

## Installation

Use Linux and Python 3.12. The pinned runtime uses PyTorch 2.5.1 / CUDA 12.4.
Run commands from the repository root.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install pip==25.1.1 setuptools==80.9.0 wheel==0.45.1
python -m pip install -r requirements.lock
python -m pip install --no-deps --no-build-isolation -e .
```

Check CPU imports, dry-run plans and protocol primitives without benchmark data,
training or optimizer steps:

```bash
PYTHONDONTWRITEBYTECODE=1 CUDA_VISIBLE_DEVICES='' MPLBACKEND=Agg python scripts/smoke.py
PYTHONDONTWRITEBYTECODE=1 CUDA_VISIBLE_DEVICES='' MPLBACKEND=Agg python scripts/smoke_rebuttal.py
```

## Data preparation and main AE experiment

Acquire the exact inputs in the [data preparation guide](docs/data/DATA_PREPARATION.md).
The JSON manifests under `reference/data/` identify dataset files and preprocessing;
they contain no detection results. Hyperparameters and evaluation rules are in
[the protocol](docs/protocols/PROTOCOL.md) and `configs/section5_ae.toml`.

```bash
python scripts/reproduce.py validate-data --raw-root data/raw
python scripts/reproduce.py prepare-data --raw-root data/raw --processed data/processed
python scripts/reproduce.py plan
python scripts/reproduce.py run --dry-run --devices cpu
python scripts/reproduce.py run --devices 0,1,2,3 \
  --processed data/processed --workspace workspace/ae
python scripts/reproduce.py aggregate --workspace workspace/ae --output outputs/ae_derived
python scripts/make_tables.py --evidence outputs/ae_derived \
  --core-only --output outputs/ae_tables
MPLBACKEND=Agg python scripts/render_figures.py \
  --cells outputs/ae_derived/core_cells.csv \
  --objective outputs/ae_derived/core_objective.csv --output outputs/ae_figures
python scripts/bootstrap_ci.py --input outputs/ae_derived/core_objective.csv \
  --output outputs/ae_intervals.csv
```

Use `--devices 0` for one GPU or `--devices cpu` for CPU execution. Optional
`--datasets` and `--seeds` filters select partial runs; complete the grid before
full aggregation. Repeating `run` resumes completed matching outputs. Raw scores,
labels, logs and checkpoints are written under the workspace. Postprocessing
output directories must be new. The primary detection metric is trapezoidal
PR-curve AUC; the inherited engine's legacy AP log field is not used.

## Score-shift analysis and adaptation variants

Complete the core experiment and aggregation first. Keep variants in the same
workspace to reuse matched source checkpoints.

```bash
python scripts/analyze_score_shift.py --workspace workspace/ae \
  --cells outputs/ae_derived/core_cells.csv --output outputs/score_shift
python scripts/reproduce_variants.py plan
python scripts/reproduce_variants.py run --devices 0,1,2,3 \
  --processed data/processed --workspace workspace/ae
python scripts/reproduce_variants.py aggregate --workspace workspace/ae \
  --core-derived outputs/ae_derived --output outputs/variant_derived
python scripts/make_tables.py --variants-only --evidence outputs/variant_derived \
  --output outputs/variant_tables
```

The [variant guide](docs/guides/SECTION43_44.md) describes M2N2, FPM, SANA,
update cadence, label perturbations, masks and matched aggregation.

## Additional experiments

The [additional experiment guide](docs/guides/REBUTTAL.md) documents input/loss
controls, count matching, distribution shifts, calibration, future probes,
checkpoint gaps, window sensitivity, VUS/Affiliation and method extensions.
Begin by indexing your completed core reproduction:

```bash
python scripts/prepare_rebuttal_inputs.py core --derived outputs/ae_derived
```

This adapter requires the fixed entity identities in `configs/rebuttal_support.json`.
That configuration contains only dataset/entity identifiers, not metrics or
experimental results. If fresh common support differs, the adapter fails rather
than silently changing the experimental protocol. Several historical validators
also enforce reference counts or diagnostic identities; fresh training differences
may cause those checks to fail. Do not alter their constants to force a pass.

Full training and adaptation require the benchmark data and suitable compute.
Numerical behavior can vary across hardware and runtime versions.
